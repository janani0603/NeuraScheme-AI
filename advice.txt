SECTION 5 — GROQ / LLAMA API USAGE
--------------------------------------------------------------------------------

File: backend/app/agents/gemini_client.py  (repurposed, kept same filename)

Correct usage pattern:

    from groq import AsyncGroq
    client = AsyncGroq(api_key=settings.GROQ_API_KEY)
    response = await client.chat.completions.create(
        model=settings.GROQ_MODEL,
        messages=[{"role": "user", "content": prompt}],
        temperature=0.3,
        max_tokens=1024,
    )
    text = response.choices[0].message.content.strip()

The generate(prompt, temperature) function is the single entry point.
All agents call: from app.agents.gemini_client import generate

Model used: llama-3.3-70b-versatile
- Free tier on Groq with generous rate limits
- Much higher limits than Gemini free tier
- Other available models: llama-3.1-8b-instant (faster), mixtral-8x7b-32768

SECTION 7 — BACKEND API ROUTES (all implemented)
--------------------------------------------------------------------------------

Auth (prefix: /auth)
  POST /auth/register     → RegisterRequest → TokenResponse (JWT)
  POST /auth/login        → LoginRequest → TokenResponse (JWT)

Users (prefix: /users)
  GET  /users/me          → UserProfileResponse (requires JWT)
  PUT  /users/me          → UpdateProfileRequest → UserProfileResponse (requires JWT)

Schemes (prefix: /schemes)
  GET  /schemes                       → SchemeListResponse (paginated, filterable)
  GET  /schemes/{slug}                → SchemeResponse
  GET  /schemes/filters/categories    → list of categories
  GET  /schemes/filters/tags          → list of tags
  GET  /schemes/filters/levels        → list of levels
  POST /schemes/{slug}/save           → save scheme to user profile
  DELETE /schemes/{slug}/save         → unsave scheme from user profile

  Query params for GET /schemes:
    keyword, level, category, tag, page, page_size, sort_by, sort_order

Recommendations (prefix: /recommendations)
  POST /recommendations/check         → EligibilityRequest → RecommendationListResponse
  GET  /recommendations/me            → RecommendationListResponse (requires JWT)
  POST /recommendations/me/refresh    → RecommendationListResponse (requires JWT)

AI (prefix: /ai)
  POST /ai/recommendations            → full LangGraph pipeline (requires JWT)
  POST /ai/recommendations/from-profile → uses saved profile (requires JWT)
  POST /ai/assistant                  → AssistantRequest → AssistantResponse (requires JWT)
  GET  /ai/conversations              → List[ConversationResponse] (requires JWT)
  DELETE /ai/conversations/{id}       → 204 No Content (requires JWT)

Admin (prefix: /admin)
  GET  /admin/stats                   → basic platform stats (admin role)

SECTION 10 — AUTHENTICATION DETAILS
--------------------------------------------------------------------------------

- JWT Bearer token authentication
- Token stored in frontend localStorage
- Token format: Authorization: Bearer <token>
- Token expiry: 60 minutes
- get_current_user dependency: decodes token → fetches user from MongoDB

SECTION 13 — AI PIPELINE (LangGraph)
--------------------------------------------------------------------------------

File: backend/app/agents/workflow.py

Graph nodes (in order):
  1. profile_agent       → validates/normalizes profile
  2. retrieval_agent     → MongoDB Atlas Vector Search → fallback text search
  3. eligibility_agent   → rule-based scoring + optional Groq assist (borderline)
  4. recommendation_agent → combined score + Groq re-ranking of top 20
  5. explanation_agent   → Groq explanations for top 10, fallback for rest

Combined score formula:
  (eligibility_score/100 * 0.60) + (vector_score * 0.25) + (completeness * 0.15)

Groq is called for:
  - Borderline eligibility interpretation (score 35–45, eligibility text > 100 chars)
  - Re-ranking top 20 schemes
  - Explanations for top 10 schemes
  - All assistant chat responses

All Groq calls have try/except with fallback — pipeline never crashes on API failure.
